# Weekly Action Reminder Skill

Send a reminder email for **open approved actions** from the committed reminder snapshot.

## Data sources (orchestration repo)

1. `docs/reminders/latest-reminder.json` — snapshot exported at archive time
2. `docs/reminders/recipients.json` — `to[]` and `subjectPrefix` (fallback: `recipients.example.json`)

If `latest-reminder.json` is missing or stale, stop with: run archive + `npm run export:reminder` first.

## Privacy

- Never deanonymize anonymous feedback.
- Use team/process language only.
- Do not modify action status or retro data files.
- Email contains action titles and descriptions only — no feedback author names.

## Compose email

**Subject:** `{subjectPrefix} Open actions — {title} ({period})`

**Body (HTML preferred):**

- Sprint title, period, team, archived date
- Bullet list of **open** actions: `ACT-####` — title, owner, target date, short description
- One-line themes summary from `reportExcerpt.themesSummary` if present
- Footer: generated by Retrospective Lab; replies not monitored

If `openActions` is empty, send a short note that there are no open approved actions for the latest archived retro.

## Send via Gmail

Use the **Cursor Gmail plugin** (`user-gmail`):

- Tool: `send_message`
- `to`: from `recipients.json`
- `subject` and `htmlBody` (plus plain `body` fallback)

Do **not** use Lokka, Microsoft Graph, or Slack for this workflow.

## Dry-run mode

When user asks for dry-run or `--dry-run`:

1. Read snapshot and recipients
2. Show composed subject and body in chat
3. Do **not** call `send_message`

## Automation mode

When run from Cursor Automation (Sunday cron):

1. Read committed files from `IslamFathyy/retro-lab` on `main`
2. Send via Gmail MCP (cloud OAuth required at cursor.com/agents)
3. Do not merge PRs or change repository files
