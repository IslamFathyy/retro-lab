## Prerequisites

1. Clone `retro-lab` and open `retro-lab.code-workspace` in Cursor.
2. Start servers:

```powershell
cd repos/retro-api && npm start    # http://localhost:3001
cd repos/retro-web && npm start    # http://localhost:8080
```

3. Demo data exists. Check:

```powershell
cd repos/retro-api && npm run retro:status
```

If `hasData` is false, run `/seed-demo-retro` first.

4. Pick a retro in `open` status (e.g. `RETRO-2026-001` from `suggestedWorkflowTarget`).

## Pass checklist

| Check | Expected |
|-------|----------|
| API tests | `npm test` in `retro-api` passes (verifier sub-agent) |
| Analysis file | `repos/retro-api/data/retrospectives/RETRO-2026-001/analysis.json` exists |
| Generated by | `"generatedBy": "cursor-agent"` |
| Themes | Each theme cites real `feedbackIds` from that retro |
| Suggestions | `suggestedActions` array with `ownerTeams` from `config/action-teams.json` |
| Sub-agents ran | `.cursor/logs/subagent-activity.log` has entries for `feedback-analyst`, `improvement-advisor`, `verifier` |
| Privacy | No anonymous author names in analysis; team/process language only |
| Optional UI | `/validate-retro-ui RETRO-2026-001` — analysis page shows themes and suggestions |

---

## Fail checklist (common fixes)

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Close fails | Fewer than 3 feedback items | Add feedback or check `config/guardrails.json` → `close.minFeedbackCount` |
| Import fails | Unknown `feedbackId` in payload | Re-run sub-agents; cite only IDs from feedback files |
| Import fails | Missing `ownerTeams` on suggestion | improvement-advisor must use ids from `config/action-teams.json` |
| No sub-agent log lines | Sub-agents skipped or hooks not configured | Follow `/analyze-retro` command; check `.cursor/hooks.json` |
| API connection error | retro-api not running | `cd repos/retro-api && npm start` |
